学習用にAgentCodingで生成したデモです

64×64×64の空間で、1個の生物パーティクルが地表を移動して物質を残します。堆積物は地形に少しずつ取り込まれます。生物としての成長・繁殖やParticle Lifeの相互作用はまだ実装していません。

- 「実行」で開始、「停止」でシミュレーションと連続描画を止めます
- ドラッグで回転、ホイールまたは2本指のピンチで拡大縮小します
- 「最初から」で地形と粒子を初期化します。時間倍率は1〜4倍です
- 青緑のブロックが初期地形、黄土色が堆積物、黄色い球が唯一の生物です

## データと更新

座標はY-up、1ボクセルの幅は1です。初期地形は数式から生成し、画像やモデルの素材は使っていません。カメラは平行投影です。

### 粒子から堆積要求を残す

```wgsl
atomicAdd(&pending[address(vec3u(cell.x, y, cell.y))], 256u);
```

地形とは別のStorage Bufferに、堆積する物質の量を蓄積します。256単位が1ボクセル分です。現在の粒子は1個ですが、将来複数の粒子が同じセルへ加算する場合も考え、整数Atomicを使います。

粒子は水平方向に曲がりながら進み、領域の端では中央へ向きを変えます。移動先の列を調べ、地表の上に高さを合わせます。これは経路探索や物理的な歩行ではなく、堆積を確認するための移動ルールです。

### 地形への取り込み

```wgsl
let p = vec3u(local.x, local.y, local.z + u32(settings.step.z) * 4u);
let amount = min(min(requested, 16u), 256u - fill);
```

Z方向に4セルずつ、16領域に分けて順番に更新します。担当する領域が回ってきたとき、蓄積場から最大16単位を地形へ取り込みます。取り込まれた量に合わせてボックスの高さが増します。

初期地形と堆積物は同じ64³の配列に保持します。下位9bitが充填量（0〜256）、bit 9が堆積物の区別です。距離を保持するSDFではありません。重力による崩落・侵食・物質の補給や枯渇は扱いません。

### シミュレーションと描画の周期

```ts
while(accumulator>=1/60 && count<24) {
  demo.step(); accumulator-=1/60; count++;
}
```

シミュレーションは固定1/60秒で進め、描画フレーム数から分離します。16ステップで地形全体を一巡し、1ボクセル分の要求は最短で約4.3シミュレーション秒かけて取り込みます。時間倍率は固定ステップを進める回数を変えます。タブを隠すと自動停止し、非表示だった時間の追いつき処理はしません。

### 表面ボクセルの描画

```wgsl
visible[atomicAdd(&draw.instances, 1u)] = i;
```

空セルと完全に囲まれたセルを除き、描画するボクセル番号をCompute Shaderでまとめます。その件数をIndirect BufferのInstance Countに書き、1回のIndirect Drawでボックスを描画します。CPUへの件数のReadbackは行いません。D3D12のExecuteIndirectに近い役割ですが、WebGPUでは`drawIndirect`に引数を渡します。

表示は立方体のままで、ボクセル同士の境界がわかるよう横幅に小さな隙間を設けています。粒子は手続き的に作る球、空間の境界は線分です。DepthはReversed Zで統一しています。ライティングは固定方向の簡易的な陰影で、Shadow Mapは使っていません。

## 現在の範囲

初期段階として、GPUでの移動、堆積要求、分散更新、描画の接続を確認します。粒子は物質を無制限に置けます。地形の上端付近では新しい堆積要求を止めます。堆積しきったセルに残った要求を隣のセルへ運ぶ処理はありません。

将来の陰関数による滑らかな表面描画や、生物と環境の相互作用は、このボックス描画とは別に検討します。
